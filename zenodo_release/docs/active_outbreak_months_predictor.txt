ACTIVE OUTBREAK-MONTHS PREDICTOR: CONSTRUCTION AND INTERPRETATION
================================================================

Purpose
-------
This document records how the active outbreak-months predictor is constructed
for the country-month analysis. The primary predictor summarizes recorded
outbreak activity in the 12 calendar months BEFORE a request month. It does
not estimate the number of cholera cases in those months.

Implementation
--------------
Construction script: analysis/main/code/research_pipeline/data/build_active_outbreak_panel.py
Constructed panel: analysis/main/outputs/analysis_data/active_outbreak_panel.csv

Inputs are (1) the Zheng et al. outbreak-record file, including country,
start_date, and end_date, and (2) the audited country-month request-outcome
panel. The script does not use total_suspected_cases to construct this
predictor and does not reclassify reactive or all-request outcomes.

The code constructs a monthly history from July 2013 through December 2019
for the 25 countries in the outcome panel. The estimation sample is July 2014
through December 2019: 66 months per country, or 1,650 country-months.
Outbreak records are matched to those countries using the country-name
crosswalk in the script. The source code TZA_zanzibar (one Unguja record)
is assigned to Tanzania, consistent with the country-month unit and with
the descriptive outbreak count. The raw source file is unchanged.

Step 1: Number of recorded outbreaks active in each month
---------------------------------------------------------
For each source outbreak record, the script converts its start_date and
end_date to calendar months. It adds 1 to every month from the start month
through the end month, INCLUSIVE, within the available history. An outbreak
that overlaps a calendar month even for one day counts as active that month.

Let A[c,m] be the number of source outbreak records active in country c
during calendar month m. If two separate records overlap the same month,
both contribute: A[c,m] increases by 2. The records are not merged into a
single country-level outbreak. Consequently, A[c,m] depends in part on how
outbreaks are delineated and recorded in the source data.

Relevant construction logic in the script, simplified:

    for each outbreak record:
        for month from start_month through end_month (inclusive):
            active[(country, month)] += 1

The resulting panel column is active_outbreaks_this_month.

Step 2: Sum prior-month outbreak activity
-----------------------------------------
For a country-month observation t and lag length L, the raw predictor is

    B[c,t,L] = A[c,t-1] + A[c,t-2] + ... + A[c,t-L].

The request/outcome month t is EXCLUDED. The primary analysis uses L = 12;
the construction script also creates L = 1, 3, and 6 for robustness checks.
For example, the July 2014 observation uses July 2013 through June 2014
for its 12-month predictor.

Exact pandas operation, applied separately to each country's chronologically
ordered monthly history:

    s.shift(1).rolling(L, min_periods=L).sum()

The output column is active_outbreak_months_prior_12m for the primary
predictor, with analogous names for the other lag lengths. shift(1) excludes
the current month; min_periods=L requires a full preceding window.

The unit is an "outbreak-month": one recorded outbreak active in one month.
An outbreak active in three months contributes three outbreak-months. Two
recorded outbreaks active in the same month contribute two outbreak-months.
Therefore this variable is NOT a case count, a count of unique outbreaks,
or a count of months with at least one outbreak.

Worked example
--------------
Suppose one record is active July-September and another August-October:

    Month                    July   August   September   October
    Active records A[c,m]      1       2          2         1

For a November request-month, these four prior months contribute
1 + 2 + 2 + 1 = 6 outbreak-months. If the other eight months in the prior
12-month window have no recorded active outbreaks, B[c,November,12] = 6.
The two records' eventual case totals do not enter this calculation.

Step 3: Log transform and between/within decomposition
------------------------------------------------------
The regression predictor is the natural-log transformation

    X[c,t,L] = ln(1 + B[c,t,L]).

For the example above, X = ln(1 + 6) = ln(7), approximately 1.946.
Zero outbreak-months remain zero after transformation.

The decomposition is performed on the LOGGED values, over the 66 estimation
months for each country:

    Between[c,L]  = mean over t of X[c,t,L]
    Within[c,t,L] = X[c,t,L] - Between[c,L].

These are the columns ending in _between and _within. In particular,
Between is the mean of 66 logged monthly values, NOT the log of the mean
raw outbreak-month count. Within measures how far a month's logged prior
activity lies above or below that country's own average logged activity.
Four countries with no variation in this predictor across the estimation
period contribute no within-country predictor variation.

Interpretation and measurement limits
-------------------------------------
This is a retrospective measure. Source start/end dates, outbreak
ascertainment, and reporting may be revised or established after the fact;
the predictor should not be described as information necessarily available
to decision-makers in real time. A zero means no outbreak activity recorded
by this source for that country and window, not proof of zero cholera.
Different surveillance intensity or the granularity of subnational
outbreak records can change the measured count. The predictor does not
measure outbreak size, severity, case counts, or outbreak-to-request delay.

Reproduction and checks
-----------------------
From the repository root, run the full package:

    python3 -B run_reproduction.py

Or, from analysis/main/code, construct only the panel:

    python3 -m research_pipeline.data.build_request_outcomes \
      --requests ../../../data/source/requests.csv \
      --output ../outputs/analysis_data/request_outcomes.csv

    python3 -m research_pipeline.data.build_active_outbreak_panel \
      --outbreaks ../../../data/source/zheng_outbreak_records.csv \
      --outcomes ../outputs/analysis_data/request_outcomes.csv \
      --output ../outputs/analysis_data/active_outbreak_panel.csv

The construction script checks source dates, country matching, duplicate
country-months, the balanced 25-by-66 estimation panel, and request-event
totals. The request outcomes should remain 58 reactive event-months and
73 all-request event-months across 1,650 country-months. These checks
validate panel integrity; they do not establish that all true outbreaks
were captured in the source.

Possible concise Methods wording (draft; verify against the final manuscript)
-------------------------------------------------------------------------
"For each country-month, we counted recorded outbreaks active in each of
the preceding 12 months and summed these monthly counts. An outbreak
spanning multiple months contributed one outbreak-month in each active
month; an outbreak's final suspected-case total was not used. We applied
ln(1 + x) to the sum, then separated each country's mean transformed value
over the estimation period from monthly deviations around that mean."
